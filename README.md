# Halifax Sourced

Halifax Sourced is a Halifax-focused restaurant, menu, specials, event, and neighbourhood discovery interface.

## 2026 ground-up UI rebuild

The current interface was rebuilt from a clean visual baseline using the approved Halifax Sourced logo, coastal design references, and static design asset kit. The previous page structure and styling were replaced rather than reskinned.

The rebuild intentionally preserves and expands the repository's collection and ingestion layer:

- curated restaurant records
- OpenStreetMap restaurant import
- reviewed local/new-opening discovery records
- Nova Scotia public food-inspection index
- restaurant-owned website signal collection
- verified direct menu and specials source pages
- structured restaurant-owned event dates
- restaurant-owned RSS/Atom feed discovery and signal collection
- official social-profile discovery from restaurant-owned websites
- restaurant-owned reservation, ordering, menu, event, ticket and newsletter link discovery
- Meta Graph API Facebook/Instagram post-signal ingestion when approved credentials are configured
- Halifax-wide event collection from public calendars, venues, teams and institutions
- SQLite/catalog build artifacts
- owner-submission import path
- validation and data-ingestion documentation

The site is static and GitHub Pages-friendly. Hash routing is used so the discovery views can deep-link without requiring a server-side SPA fallback.

## Main views

- `#home` — editorial discovery homepage with featured restaurants, upcoming city events, specials, and new/opening leads
- `#explore` — searchable/filterable restaurant results, including menus, specials, events, patios, openings, social profiles, reservations, and online ordering
- `#events` — Halifax-wide upcoming sports, music, arts, food/drink, festival, community, comedy and outdoor events with category/date-window filters and progressive loading
- `#specials` — direct specials/happy-hour source leads
- `#menus` — restaurants with direct menu-source coverage
- `#map` — Leaflet map/list discovery
- `#restaurant/<id>` — restaurant detail, official social/related links, menus, specials, events, actions, and source evidence
- `#saved` — device-local saved places

## Restaurant discovery

The core catalogue is deliberately multi-source rather than dependent on one directory. It combines curated records, OpenStreetMap, restaurant-owned websites, Nova Scotia public registry evidence, and a reviewed local-discovery layer for new openings that have not propagated into slower datasets yet.

`data/discovered-restaurants.js` contains reviewed additions. `data/discovery-overrides.json` records why a provisional listing was approved and which source supports it. This layer is how newly observed openings such as Sakaba can appear without pretending incomplete address/site/social details are already verified.

## Social and related first-party links

First-party discovery is stored in `data/first-party-sources.js`. The crawler starts with the restaurant-owned website and extracts links the restaurant itself publishes. Supported social/navigation platforms include:

- Instagram
- Facebook
- X
- TikTok
- YouTube
- LinkedIn
- Bluesky
- Threads/Linktree when linked and recognized

It also records useful first-party actions such as:

- menu
- reservations
- events
- online ordering
- newsletter
- tickets

These links are visible on restaurant detail pages and are searchable/filterable through Explore. A profile shared by several locations of one brand may still be shown as an official navigation link, but it is marked as a shared brand profile and is **not** automatically treated as location-specific post evidence.

Facebook and Instagram post collection remains API-only. `data/social-signals.js` is generated by `scripts/import-meta-social.mjs` when suitable Meta credentials are available. The importer classifies recent post/caption text in memory and retains only source IDs, permalinks, timestamps, platform metadata, and matched discovery keywords. It does not scrape Facebook/Instagram HTML or retain raw post text. See `docs/social-and-first-party-ingestion.md`.

Website feed results are stored in `data/website-feed-signals.js` without retaining long feed bodies. Feed/social signals remain historical evidence, but unstructured items set current consumer flags only when they have a parseable publication timestamp no more than 60 days old.

## Halifax-wide events

Restaurant-specific structured events remain in `data/structured-events.js`, while broader city events are published to `data/city-events.js` / `data/build/city-events.json`.

The city pipeline currently combines sources including:

- Tourism Nova Scotia event listings, location-filtered after ingestion
- Scotiabank Centre
- Light House Arts Centre
- The Carleton
- Neptune Theatre
- Halifax Mooseheads home schedule
- HFX Wanderers home schedule
- Halifax Tides home schedule
- Halifax Thunderbirds when extractable
- Halifax Convention Centre
- Symphony Nova Scotia
- selected Halifax, Dartmouth and Bedford Halifax Public Libraries branches
- HalifaxEvents.ca when its current markup yields structured records

`data/event-source-registry.json` and `data/event-source-supplements.json` define the source registry. `scripts/import-city-events.mjs` and `scripts/import-supplemental-city-events.mjs` perform collection. `scripts/sanitize-city-events.mjs` then restricts the public event dataset to Halifax, Dartmouth and Bedford and normalizes categories. Province-wide Tourism Nova Scotia records are never allowed to default to Halifax merely because a location could not be parsed.

The current category vocabulary includes Sports, Music, Arts, Food & Drink, Festivals, Markets, Comedy, Outdoor, Community and Other. The Events UI exposes category filters, 7/30/90-day windows, All Upcoming, and progressive Load More behavior.

## Data integrity

The UI distinguishes source coverage from consumer ratings. It does not fabricate live review scores, event dates, special prices, or reservations when those fields are not present in the collected data. Event and special signals are presented as leads when they require confirmation.

Restaurant imagery is separately provenance-gated. Production photos are loaded from `data/restaurant-media.js` only when the media record has an exact restaurant ID, approved review state, explicit permission confirmation, source URL, source type, and documented rights basis. Unreviewed or merely public images are not rendered. See `docs/media-provenance.md`.

Menu and specials discovery separates a general website/keyword signal from a direct source page. `data/verified-source-pages.js` stores exact-ID menu/specials links that passed the source-page verification contract. The UI prefers those records, falls back to direct official-site candidate links while verification coverage grows, and does not treat a generic restaurant homepage as proof that a menu exists. See `docs/verified-source-pages.md`.

The city-event gate rejects malformed records and out-of-scope municipalities. It also records source failures and coverage warnings rather than silently substituting invented data.

## Development

Serve the repository root over HTTP. For example:

```bash
node scripts/dev-server.mjs
```

Then open the local URL printed by the script.

## Data refresh

Existing import scripts remain under `scripts/`. See `docs/ingestion-compliance.md`, `docs/media-provenance.md`, `docs/structured-events.md`, `docs/verified-source-pages.md`, `docs/social-and-first-party-ingestion.md`, and `data/source-contract.json` before extending collection.

Owner media workflow:

```bash
node scripts/import-owner-submissions.mjs
# review normalized media and set reviewState=approved only when rights are verified
node scripts/build-restaurant-media.mjs
node scripts/check-data-integrity.mjs
```

Restaurant-specific structured event preview:

```bash
node scripts/import-structured-events.mjs
node scripts/check-data-integrity.mjs
```

Halifax-wide city event refresh:

```bash
node scripts/import-city-events.mjs
node scripts/sanitize-city-events.mjs
node scripts/import-supplemental-city-events.mjs
node scripts/sanitize-city-events.mjs
node scripts/check-city-events.mjs
```

Verified menu/specials source preview:

```bash
node scripts/verify-official-source-pages.mjs
node scripts/check-data-integrity.mjs
```

First-party website/social source discovery:

```bash
node scripts/discover-first-party-sources.mjs
node scripts/sanitize-first-party-sources.mjs
node scripts/import-first-party-feed-signals.mjs
node scripts/check-expanded-sources.mjs
```

Meta social signal pull:

```bash
META_FB_ACCESS_TOKEN=... \
META_IG_ACCESS_TOKEN=... \
META_IG_USER_ID=... \
node scripts/import-meta-social.mjs
node scripts/check-expanded-sources.mjs
```

GitHub Actions secrets used by the Meta pull are `META_FB_ACCESS_TOKEN`, `META_IG_ACCESS_TOKEN`, and `META_IG_USER_ID`. The importer exits successfully with an explicit missing-credential state when these are not configured; it never falls back to scraping.

## Preview workflows

- `Source Expansion Preview` refreshes website signals, verified source pages, restaurant events, first-party sources, feeds and permitted Meta signals.
- `Social Source Preview` refreshes the focused first-party social/feed/related-link layers.
- `City Events Preview` refreshes and validates the Halifax-wide event dataset.
- `Restaurant Discovery Preview` evaluates broader/new-opening restaurant discovery sources.

Preview workflows are **artifact-only** on feature branches. They do not push generated commits back into an active pull-request branch. This prevents bot-authored refresh commits from invalidating or suppressing the PR Quality Gate. Generated output should be reviewed and deliberately promoted.

## Deployment and quality gate

GitHub Pages deployment is gated behind the `Quality Gate` workflow. Pull requests and `main` run JavaScript syntax checks, data-integrity gates, city-event scope validation, restaurant-discovery checks and Playwright UI verification. The gated Pages workflow deploys the exact `main` commit SHA that passed verification.
