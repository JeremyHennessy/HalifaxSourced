# Reviewed navigation-record quarantine

## Scope and evidence

`data/quarantine/library-store-navigation-20261027.json` is a **non-active evidence archive**, not a source feed or an event dataset. It preserves all 89 complete accepted navigation records (85 Halifax Public Libraries; 4 Bedford), their original IDs and observation timestamps, per-record canonical SHA-256 values, exact guards, and evidence links. The archived records exactly matched accepted `data/build/city-events.json` at commit `0ea1a8570b46303597ee887b7b7a2976982e92d5`.

The decision applies only to those exact records: each was titled `Library Store` and linked to `https://www2.halifaxpubliclibraries.ca/store/`, not an event-detail occurrence. This is an offline review of preserved evidence, **not a fresh publisher observation or a cancellation finding**. The clean project archive retains the accepted snapshot commit/hash, public workflow/artifact links and member hashes, and original source-observation window. The separate `activeQuarantineIds` decision list explicitly activates the reviewed projection policy.

Six genuine BiblioCommons detail occurrences are listed as `protectedDetailIds`. They are not quarantine decisions. Their status remains unresolved: the prior manual read returned a cached anti-bot challenge. No source retry, bypass, cancellation inference or reviewed-retention exception is introduced.

## Application and safety

The pure `scripts/lib/reviewed-event-quarantine.mjs` helper is used by both:

- `sanitize-city-events.mjs`, before municipality/category normalization and canonical deduplication; and
- `reconcileFutureEventLosses`, on both previous and current records before identity reconciliation and future-loss comparison. The production reconciliation command loads the required archive explicitly.

A record must match an explicitly active ID, exact source ID/title/event URL/start/end/observation timestamp, **and the entire archived raw-record SHA-256**. Source kind, source URL, additional identity aliases and any other changed content therefore cannot disappear under an older review. A changed reviewed ID remains in the helper's output and produces a blocking mismatch. Production commands write diagnostic receipts and refuse to overwrite candidate/runtime payloads on a mismatch. New IDs are never quarantined merely because their title, day or URL looks similar.

Archive corruption, duplicate decisions, missing raw records and attempts to quarantine a protected detail ID fail closed. No omission thresholds, grace periods, source failure/hold policy, collection status or source clocks are changed. Collector `sourceStats` remain collection receipts, not quarantine counts.

Receipts:

- `artifacts/city-event-quarantine-report.json`: exact exclusions and mismatches for the sanitation invocation;
- `scopeAudit.reviewedQuarantine`: the sanitation receipt in its output projection;
- `artifacts/city-event-source-drift-report.json` → `reviewedQuarantine.previous/current`: both refresh-comparison receipts, including exclusions even when unresolved omissions block publication.

The receipts count each invocation, so a second sanitation of already-quarantined output reports zero additional exclusions. Event content and IDs remain idempotent. Review/build times are not substituted for source observation times.

## Reversibility

Accepted input snapshots are not regenerated by this change. The archive keeps all complete originals permanently retrievable. A separately reviewed restoration can remove an ID from `activeQuarantineIds` while leaving its archived record/evidence untouched, then rebuild from the preserved accepted input. For a future input that no longer contains the row, restoring it requires an explicit reviewed data restoration; the helper never resurrects absent events automatically. Reverting the projection integration also leaves archived evidence intact. Do not delete archive records to change active policy.
